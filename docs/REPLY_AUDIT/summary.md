## Engine rules verified by reading code

- **R1** A choice with a resolvable nextNodeId loads that scene and ignores nextSegment; otherwise nextSegment loads that segment; a missing segment/scene key leaves the scene in place with sceneDone=true (terminal). — `narrativeStore.ts:636,654`
- **R2** Segment narrative is filtered by per-node conditions using gameState/activeFlags captured BEFORE the choice applies its stateChanges and flags. — `narrativeStore.ts:410,666`
- **R3** A nextNodeId target is used raw from SCENE_REGISTRY: no filterNarrative, no `dialogue` normalisation, no prerequisites, no exclusive[] redirect. — `narrativeStore.ts:636,654-655`
- **R4** Visible choices = choices whose `conditions` all pass (choice-level `prerequisites` are ignored); an empty list becomes the synthetic "Continue…" (ENGINE_CONTINUE_ID), which completes the scene with no effects (narrativeStore.ts:385). — `NarrativeEngine.ts:65,76; NarrativeScene.tsx:96-98`
- **R5** Conditions: {type:"flag",flag,value} = membership; {stat,operator,value} with dot paths, `flags.x`, top-level stats and PATH_ALIASES; an unknown path is false; bare {flag,value} has no stat and throws. — `conditionEvaluator.ts:52,110`
- **R6** `statEffects` (as add) apply only when `stateChanges` is empty. — `narrativeStore.ts:449-457`
- **R7** Reactions: only the clicked choice's reactions are queued; the strip renders only while !sceneDone; the reset effect keyed on the `choices` array clears them. — `ConversationPanel.tsx:486-489,553-562,1228`
- **R8** Every scene, including type social_event, renders through NarrativeScene; `socialInteractions` are never read. — `GameLayout.tsx:62-65 (SocialEvent imported nowhere)`
- **R9** family_dinner_recurring / intelligence_briefing_recurring append injected segment narrative to whatever currentScene.narrative is, keyed on the scene id only. — `NarrativeScene.tsx:58-71`
- **R10** delayWeeks 0 chain triggers call injectScene right away (no condition/probability check), inserting the target after the current queue item; injectScene skips visited targets. — `narrativeStore.ts:475-498; weekStore.ts:1597-1621`
- **R11** A segment without its own monologue inherits the current monologue; ConversationPanel shows a monologue only when its text changes. — `narrativeStore.ts:668`

## S6 rule (verified)

- Reactions play only for the choice they belong to (handleChoice looks up the clicked id). They never play for every choice.
- They are shown only while !sceneDone, so reactions on terminal choices are never eligible.
- Even eligible ones are cleared in the same commit by the `[choices]` reset effect, because NarrativeScene rebuilds the choices array every render. D2 measured their lifetime with a MutationObserver (see E1).
- socialInteractions never play: SocialEvent.tsx is unmounted, so those scenes show only their top-level `choices` (or the engine "Continue…" when empty).

METHODOLOGY NOTES (read this before the report):
- Flag SETs are collected from every choice `flags: [...]` array.
- Flag READs are collected from `prerequisites`/`conditions` wherever they appear (scene-level,
  choice-level, chainTrigger-level) AND from scene-level `prerequisiteFlags`. Two condition shapes
  exist in this codebase and both are handled: {stat:"flags.x",...} and {flag:"x",...}.
- "stateChanges" in the spec covers both field names actually used in the data: `stateChanges` and
  `statEffects` — both are treated as equivalent for dead-end detection.
- Agenda sceneIds "__budget__", "__vote__", "__constitution__", "__cabinet_reshuffle__" are synthetic
  sentinels handled directly in weekStore.ts (open a UI phase, not a narrative scene). They are NOT
  counted as broken links; listed separately below for transparency.
- `__project__*` sceneIds ARE real scenes (src/data/narrative/projects/) and resolve normally.
- Bonus checks beyond the original spec: scene-level `prerequisiteSceneIds` and `exclusive` arrays
  are also scene-id references in this codebase, and are validated under BROKEN LINKS.
- New reference category: hardcoded scene-id string literals in store files (weekStore.ts builds
  dynamic scene pools not listed in any static agenda JSON). These count toward orphan reachability
  the same as agenda/nextNodeId/chainTrigger. See STORE FILE SCENE REFERENCES below.
- New flag-SET source: `voteConfig.successFlags`/`failureFlags` in src/data/agenda/*.json items and
  in the make*VoteItem() factories inside src/stores/weekStore.ts. These flags are set dynamically
  when a synthetic __vote__ node resolves, not via a choice.flags array. See VOTE CONFIG FLAG SETS below.
- New flag-SET source: runtime mechanisms — addFlags([...]) literals in store files,
  narrativeStore mole consequence flags (merged into activeFlags), and bill signFlags in
  src/data/bills/*.json (applied by BillEngine on sign). See CODE-SET FLAG SOURCES below.
